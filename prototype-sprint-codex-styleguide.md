# 1. Implementation Priority

This site should be built to match the attached mockup's **overall look, tone, hierarchy, and structure** as closely as practical.

Codex should not treat the mockup as vague inspiration.

It should treat it as a **design target**.

That means:

- match the general layout
- match the section ordering
- match the visual tone
- match the spacing feel
- match the warm-but-not-feminine brand character
- match the card-driven information architecture
- match the CTA prominence
- match the clean product-studio look
- match the typography balance between editorial warmth and modern UI clarity

Do **not** reinvent the page into a totally different design language.

Do **not** over-index into “AI startup neon.”

Do **not** drift into soft lifestyle / feminine / wellness aesthetics.

Do **not** add decorative plants, organic blobs, or overly “cozy café” styling.

The goal is:

## Warm. Human. Competent. Product-focused. Collaborative. Fast.

# 6. Typography Direction

The mockup implies a **two-font style**, or at least two distinct typographic modes.

## Heading style
Use a serif or serif-like editorial display face for major headlines.

Desired characteristics:
- warm
- intelligent
- human
- slightly classic
- readable
- not fancy
- not wedding-invitation
- not overly delicate

Possible directions:
- Fraunces
- Merriweather
- Libre Baskerville
- Cormorant Garamond (only if used carefully)
- or another readable editorial serif

### Headline goal
Strong, elegant, and warm.

Example:
**From idea to something real.**

## Body / UI text
Use a clean sans-serif for navigation, body text, labels, cards, buttons, and supporting copy.

Possible directions:
- Inter
- Plus Jakarta Sans
- Manrope
- Geist
- Instrument Sans

### Body/UI goal
Readable, modern, and product-oriented.

## Typographic relationship
The serif should create warmth and authority.
The sans should create clarity and usability.

### Avoid
- overly playful fonts
- script fonts
- delicate feminine serif styling
- condensed tech fonts
- futuristic display fonts

---

# 7. Logo / Wordmark Direction

Use a simple and minimal wordmark treatment.

From the mockup, the mark is light and straightforward.

## Direction
- text-first
- simple logomark optional
- compact enough for navbar
- should not overpower the page
- should feel like a product/service, not a fashion brand

A simple circle mark with initials or a restrained badge can work.

But the safest path is:

## Prototype Sprint
with subtle accompanying descriptor if desired:
**Ideas into real products.**

Do not spend too much visual complexity here.

# 8. Layout Structure

Codex should follow this page structure in roughly this order.

## 1. Navbar
Contents:
- logo / wordmark
- How It Works
- Pricing
- Add-Ons
- Examples
- FAQ
- primary CTA button: **Book a Sprint**

Navbar style:
- clean
- light background
- no heavy shadow
- sticky optional
- balanced spacing
- simple CTA prominence

## 2. Hero
Two-column layout on desktop.

### Left side
- main headline
- supporting copy
- primary CTA
- secondary CTA
- short row of feature/value items

### Right side
- large visual mockup / laptop / product scene
- product-centered, not decorative

### Hero tone
This is the strongest section.
It should feel premium, clear, and focused.

### Headline style
Large editorial serif headline.
One highlighted accent word.

Example:
**From idea to something real.**

Where **real** is orange/accent-colored.

### Supporting copy
Simple, concise, not dense.

### CTA treatment
Primary:
- filled orange button

Secondary:
- outlined or lightly bordered button

### Value row
Use four compact icon + label/value items, e.g.:
- 3 Hours
- Live & Collaborative
- AI-Assisted
- Deploy When Possible

## 3. Mid-band statement
A thin or medium-height horizontal statement band.

Purpose:
- reinforce positioning
- break up the hero and body

Tone:
- slightly tinted background
- centered copy

Example intent:
**Not a giant project. Not months of meetings. Just focused time and real progress.**

## 4. “What we can build” section
Two-column or hybrid layout.

Left:
- heading
- short intro
- bullet list

Right:
- 4 feature cards / outcome cards

Possible outcomes:
- Deployed Prototype
- Landing Page
- Brand Starter
- Social Media Kit

This section should visually communicate:
**these are possible sprint outcomes**

### Note
Preserve the line indicating that in the right circumstances you can walk away with both a deployed prototype and a landing page.

That is a strong differentiator.

## 5. “How a Prototype Sprint works” section
Three-step process.

Steps:
1. Discover
2. Build Live
3. Refine & Launch

This should use:
- numbered circles or step markers
- clear headings
- concise descriptions

Also include:
- a goal/summary note card
- a testimonial or quote card to the right on larger screens

## 6. Pricing section
Three price cards:
- Prototype Sprint — 3 hours — $500
- Iteration Session — 2 hours — $300
- Iteration Sprint — 3 hours — $450

Styling:
- center emphasis on the first card
- warm border accent on active/recommended option
- clear and clean pricing
- simple footnotes or companion bullet list to the right

Also include supporting bullets such as:
- All deliverables are yours
- Source code, assets, accounts, and everything we build
- No surprises. No retainers.
- Just focused time that moves your idea forward.

## 7. Add-Ons section
Grid of compact cards / chips.

Possible add-ons:
- Brand Starter
- Landing Page
- Social Media Kit
- Content Copy
- Analytics & Tracking
- Email Automation
- Custom Integrations
- Priority Support

This should feel like a **menu of sprint priorities / optional focus areas**, not like a bloated agency service page.

## 8. Footer
Dark footer.

Should include:
- short trust/positioning statement
- logos/text references to common tools:
  - Netlify
  - Supabase
  - GitHub
  - Google Cloud
  - Stripe
- ownership statement:
  - Everything is set up in your accounts.
  - We build it together. You own it all.

Footer should feel grounded and credible.

# 9. Spacing & Density

A big reason the mockup works is that it is **not cramped**.

Codex should preserve generous spacing.

## General spacing guidance

- large vertical section spacing
- breathing room around cards
- roomy hero
- clear margin between headings and body copy
- card padding should feel comfortable
- avoid tiny compressed UI

### Approximate feel
- hero top/bottom padding: large
- section vertical padding: medium-large
- cards: medium padding with moderate border radius
- max width: reasonably wide but not edge-to-edge

## Border radius
Use soft rounded corners.

Suggested:
- buttons: 10–14px
- cards: 14–18px
- larger mockup/image containers: 18–24px

## Shadows
Very subtle.
Do not use heavy shadows.
Use either:
- subtle border
- subtle lift
- or both very gently

# 11. Iconography

Icons should be simple, thin-to-medium line icons.

Style:
- consistent stroke width
- clean
- minimal
- modern
- not playful
- not cartoonish

Use icons for:
- value props
- add-on cards
- feature bullets
- ownership/support bullets

Accent color can be used sparingly.

---

# 12. Button System

## Primary button
- filled orange
- white or near-white text
- medium-large size
- rounded corners
- strong visual priority

## Secondary button
- outline or light border
- transparent or warm off-white fill
- charcoal text
- still clearly clickable

## Button feel
- crisp
- modern
- confident
- not oversized to the point of looking cheesy

### Avoid
- giant pill buttons
- neon buttons
- excessive glow
- gradient fills

---

# 13. Card System

The site uses cards heavily.

Cards should be visually consistent.

## Card characteristics
- light warm background or white
- subtle border
- rounded corners
- modest shadow if any
- clear heading
- concise supporting copy
- enough padding
- no clutter

### Card types used
- outcome cards
- pricing cards
- quote/testimonial card
- add-on cards
- supportive info cards

Maintain a shared system.

The copy should match the current service framing.

## Tone
- direct
- human
- concise
- optimistic
- confident
- not hypey
- not overly casual
- not corporate-jargony

## Use
- short declarative sentences
- practical language
- “build together”
- “focused time”
- “real progress”

- “you own it”

## Avoid
- “10x”
- “disrupt”
- “revolutionize”
- “synergy”
- “AI-powered everything”
- “frictionless transformation”

# 15. Mobile Responsiveness

Codex should preserve the same visual character on mobile.

## Mobile priorities
- hero stack vertically
- headline remains strong
- CTAs remain high on page
- value row can wrap or stack
- cards become single-column or two-column where practical
- pricing cards should remain readable
- add-on menu should wrap gracefully
- dark footer should remain simple

Do not let mobile feel like an afterthought.

---

# 16. Animation / Motion

Keep animation subtle.

Possible use:
- small hover lift on cards
- button hover state
- soft fade/slide-in on section reveal
- subtle process-step emphasis

Avoid:
- big parallax
- flashy motion
- excessive scrolling gimmicks
- AI-style particle effects
- heavy typewriter animations
